Build factory/compute/ (the broker) so a single episode render is split across MANY heterogeneous providers simultaneously, preferring $0 capacity:
1. Provider capability model + QUOTA LEDGER: each provider declares capabilities (gpu/cpu, vram, ram, max runtime per task, concurrency, cold start, per-month free quota in its native unit: GB-s, vCPU-s, GPU-hours, credits) and the ledger tracks consumption per billing period (persisted in S3/DynamoDB of the existing story-farm stack, or local JSON fallback) so free tiers are NEVER exceeded unless the run explicitly allows paid overflow. Terms gate: only providers with verdict USE (or USE-WITH-CARE when explicitly enabled) are schedulable.
2. WORK-STEALING QUEUE across providers: frames are chunked (size adapted per provider: tiny chunks for 15-min serverless, bigger for pods); chunks are claimed via atomic leases (S3 conditional PUT If-None-Match or DynamoDB conditional write) with heartbeats; any worker on any provider pulls the next chunk it's capable of (respecting quality tier: preview chunks may go to CPU, final Cycles chunks prefer GPU unless the deadline allows CPU); stragglers are speculatively re-executed on faster providers near the end (tail-latency killer); results land in S3 via presigned PUTs (credential-free workers) and are deduplicated by frame.
3. PLANNER: given a job (frames, quality, deadline, budget), compute the mix: fill free capacity first by expected throughput (calibrated s/frame per provider x concurrency), then cheapest paid spot GPUs for the remainder to hit the deadline; output the plan (which providers, how many workers each, expected minutes, $). Re-plan live as providers succeed/fail.
