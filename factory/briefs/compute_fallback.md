# Brief: compute_fallback — provider-agnostic GPU farm with automatic fallback
(Read /home/user/story-animator/factory/briefs/_common_v2.md first; then cloud/farm/* and docs/farm.md, which are AWS-only today.)
Goal: rendering never depends on one vendor's approval. Build cloud/farm/providers/ with a common interface
  Provider.available() -> (ok, reason)   # credentials present, quota/capacity > 0, budget ok
  Provider.launch(n, gpu_class, env, startup) -> [worker handles];  Provider.list(); Provider.terminate(ids); Provider.price_per_hour(gpu_class)
and implementations:
  1. aws_ec2: wraps the existing ASG/launch-template path (reads G/VT quota via service-quotas; quota 0 => unavailable with reason).
  2. runpod: RunPod REST/GraphQL API (env RUNPOD_API_KEY; read their current API docs on the web: pods create/stop/terminate, gpuTypeId e.g. 'NVIDIA GeForce RTX 4090' / 'NVIDIA L40S', cloudType SECURE/COMMUNITY, spot/interruptible bids, containerDiskInGb, env vars, docker image, ports none). Workers boot from a public CUDA base image (e.g. runpod/base or nvidia/cuda runtime) with a STARTUP SCRIPT (no custom Docker image needed: no Docker daemon here) that installs Blender 4.2.3 (pinned tarball + sha256), pulls the repo at a pinned commit (git over https; the repo may be private — support a read-only deploy token env GIT_TOKEN, or alternatively ship the code as a tarball from S3), syncs library from S3, and runs cloud/farm/worker.py.
  3. vastai: Vast.ai API (env VAST_API_KEY; search offers by gpu_name/reliability/price, create instance with onstart script) — same startup script.
  4. local: runs workers on the current machine (CPU) — last resort.
Queue/storage stay AWS SQS + S3 (no quota needed for those); non-AWS workers get a least-privilege IAM user's keys via provider secrets/env (write the IAM policy for a 'farm-worker-external' user into the CloudFormation template; do NOT create it). Make worker.py run unchanged anywhere (it already polls SQS); ensure GPU detection works for RunPod/Vast containers (CUDA/OptiX device selection, nvidia-smi).
Scheduler: cloud/farm/scheduler.py picks providers by policy (config cloud/farm/providers.yaml: order e.g. [aws_ec2, runpod, vastai, local], per-provider max workers, max $/h, gpu classes, spot first), falls back automatically when a provider is unavailable or launches fail (insufficient capacity, quota, API errors) or when workers don't come up healthy within a timeout, rebalances mid-run, terminates idle workers, enforces the global budget ceiling, and records which provider rendered each job (manifests). Integrate with orchestrator.py ('submit' uses the scheduler; 'status' shows providers).
Price/speed table per provider+GPU used for planning (Cycles relative speed: A10G=1.0, L4~0.9, RTX4090~2.5, L40S~2.2, A100~1.8 as defaults, overridable by measured calibration).
Tests (tests/farm): unit tests with mocked HTTP for RunPod and Vast APIs (request shapes from their docs), fallback scenarios (aws quota 0 -> runpod; runpod capacity error -> vast; all down -> local), budget enforcement, startup-script lint (shellcheck if pip/apt-installable) and a dry-run that renders the startup script + launch payloads to files for review. NO real launches, no spend, no account creation.
